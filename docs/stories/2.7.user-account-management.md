# Story 2.7: User Account Management System

## Status
Draft

## Story
**As a** user with anonymous authentication,  
**I want** to upgrade to a full user account with email/password or convert back to anonymous,  
**so that** I can have persistent access across devices while maintaining the option for privacy-focused anonymous usage.

## Acceptance Criteria

1. Anonymous users can upgrade to email/password authentication without data loss
2. Users can sign up with email/password and automatically import anonymous data  
3. Users can sign in with existing email/password credentials
4. Users can sign out and return to anonymous authentication mode
5. Account upgrade process preserves all existing expense data and sync history
6. Password reset functionality is available for email/password users
7. Account management UI is accessible from settings screen
8. Graceful handling of authentication errors with user-friendly messages

### Context7 Supabase Email/Password Authentication Patterns  
[Source: Context7 /supabase/supabase-flutter documentation]

**Email/Password Sign Up:**
```dart
// Modern email/password signup
await supabase.auth.signUp(
  email: email,
  password: password,
);
```

**Email/Password Sign In:**
```dart
// Updated signInWithPassword method (Context7 v1.0.0+)
await supabase.auth.signInWithPassword(
  email: email,
  password: password,
);
```

**Password Reset:**
```dart
// Magic link password reset
await supabase.auth.signInWithOtp(email: 'user@example.com');
```

**User Management:**
```dart
// Update user information
final res = await supabase.auth.updateUser(
  UserAttributes(
    email: 'new@email.com',
    data: {
      'username': 'new_username',
    },
  ),
);
```

**Authentication State Management:**
```dart
// Listen to authentication state changes
final subscription = supabase.auth.onAuthStateChange.listen((data) {
  final AuthChangeEvent event = data.event;
  final Session? session = data.session;
  
  switch (event) {
    case AuthChangeEvent.signedIn:
      // Handle successful sign in
      break;
    case AuthChangeEvent.signedOut:
      // Handle sign out
      break;
    case AuthChangeEvent.userUpdated:
      // Handle user profile updates
      break;
  }
});
```

### Data Migration Strategy
[Source: Existing sync engine architecture analysis]

**Account Upgrade Process:**
1. Create new email/password account while maintaining anonymous session
2. Transfer data ownership from anonymous user ID to new authenticated user ID
3. Update all local and remote data records with new user context
4. Migrate sync metadata and operation history
5. Sign out anonymous session and sign in with new account
6. Verify data accessibility and sync functionality

**Rollback Strategy:**
- Maintain anonymous session until upgrade confirmation
- Ability to revert to anonymous mode if upgrade fails
- Data integrity checks at each migration step
- Error recovery with user notification

### User Experience Considerations

**Account Upgrade Flow:**
