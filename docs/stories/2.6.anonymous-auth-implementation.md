# Story 2.6: Anonymous Authentication Implementation

## Status
Approved

## Story
**As a** user,  
**I want** the app to automatically authenticate me with anonymous credentials when I first launch it,  
**so that** I can use all sync features without requiring manual login while maintaining data isolation and security.

## Acceptance Criteria

1. App automatically signs in users with anonymous authentication on first launch
2. Anonymous users have unique user IDs for data isolation via RLS policies  
3. Seamless transition from offline-only to authenticated mode without data loss
4. Anonymous session persists across app restarts until user logs out
5. All existing expense data is properly associated with the anonymous user ID
6. Anonymous authentication integrates with existing startup guard system
7. Fallback to offline-only mode if anonymous authentication fails

### Context7 Supabase Authentication Patterns
[Source: Context7 /supabase/supabase-flutter documentation]

**Modern Anonymous Authentication:**
```dart
// Anonymous sign-in (Context7 recommended pattern)
final response = await supabase.auth.signInAnonymously();
```

**Session Management:**
```dart
// Automatic session persistence (no custom state classes needed)
await Supabase.initialize(
  url: 'SUPABASE_URL',
  anonKey: 'SUPABASE_ANON_KEY',
);

// Get initial session
try {
  final initialSession = await SupabaseAuth.instance.initialSession;
} catch(error) {
  // Handle session recovery errors
}
```

**Authentication State Listening:**
```dart
// Modern stream-based auth state changes
final subscription = supabase.auth.onAuthStateChange.listen((data) {
  final AuthChangeEvent event = data.event;
  final Session? session = data.session;
  // Handle auth state changes
});
// Remember to cancel subscription
subscription.cancel();
```


### Performance Considerations
- Anonymous authentication should be fast and non-blocking
- Authentication state changes should not trigger unnecessary UI rebuilds
- Session persistence should not impact startup performance
- Fallback to offline mode should be immediate on auth failure

### Security Implementation Notes
- Anonymous user IDs are unique and cannot access other users' data
- Session tokens are managed automatically by Supabase Flutter SDK
- No sensitive data is stored locally beyond Supabase's secure session management
- Authentication failure gracefully falls back to offline-only mode
