## Dev Notes

### Current Authentication Analysis
The existing codebase uses anonymous authentication (`signInAnonymously()`) implemented in:
- `lib/core/services/authentication_service.dart` - Core auth service
- `lib/core/providers/auth_providers.dart` - Riverpod state management  
- `lib/core/startup/startup_guard.dart` - App initialization

This anonymous approach lacks:
- User credential requirements
- Data isolation between users
- Login/signup UI screens
- Password reset functionality
- Secure user session management

### Architecture Integration Points
- **State Management**: Extend existing `AuthenticationNotifier` to support email/password flows
- **Service Layer**: Add email/password methods to `AuthenticationService`
- **Routing**: Integrate auth screens into app navigation flow
- **Startup Flow**: Modify `StartupGate` to handle unauthenticated states
- **Data Isolation**: Ensure RLS policies work with authenticated users

### Context7 Supabase Integration
Based on Context7 documentation patterns:
```dart
// Sign up with email/password
await supabase.auth.signUp(
  email: email,
  password: password,
);

// Sign in with email/password  
await supabase.auth.signInWithPassword(
  email: email,
  password: password,
);

// Password reset
await supabase.auth.resetPasswordForEmail(email);

// Listen to auth state changes
supabase.auth.onAuthStateChange.listen((data) {
  final AuthChangeEvent event = data.event;
  final Session? session = data.session;
  // Handle auth events
});
```

### UI/UX Design Requirements
- **Platform Consistency**: Use `PlatformWidgets` for iOS/Android differences
- **Accessibility**: Proper labels, keyboard navigation, screen reader support
- **Responsive Design**: Handle different screen sizes and orientations
- **Theme Integration**: Follow existing `AppTheme` patterns
- **Internationalization**: Support existing l10n structure
- **Loading States**: Consistent with app-wide loading patterns

### Security Considerations
- Input validation and sanitization
- Secure password storage (handled by Supabase)
- Protection against common vulnerabilities (XSS, injection)
- Rate limiting for authentication attempts
- Secure session management
- Deep link security for password reset flows
