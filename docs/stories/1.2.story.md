# Story 1.2: Enhanced Add Expense with Receipt Photos

## Status: Done

## Story

As a user,
I want to attach photos of receipts when adding expenses,
so that I can maintain digital records and have proof of purchases.

## Acceptance Criteria

1. Users can capture or select photos when adding expenses
2. Photos are stored locally and associated with expense records
3. Receipt photos are displayed in expense details
4. Photo storage uses existing Hive database patterns
5. Camera and gallery permissions are handled properly
6. Existing expense form functionality remains unchanged

## Integration Verification

IV1: Verify that existing expense creation workflow remains functional
IV2: Verify that existing expense data model can accommodate photo metadata
IV3: Verify that existing expense list and detail views continue to work

### Data Models

**Receipt Photo Model** [Source: docs/architecture.md#Data Models and Schema Changes]

- `id`: String (UUID) - Unique identifier for the photo
- `expenseId`: String - Reference to the associated expense
- `filePath`: String - Local file path where photo is stored
- `fileName`: String - Original filename of the photo
- `fileSize`: int - Size of the photo file in bytes
- `mimeType`: String - MIME type of the photo (e.g., 'image/jpeg')
- `capturedAt`: DateTime - When the photo was captured/selected
- `createdAt`: DateTime - When the photo record was created
- `updatedAt`: DateTime - When the photo record was last updated

**Modified Expense Model** [Source: docs/architecture.md#Schema Integration Strategy]

- Add `photoIds`: List<String> - List of photo IDs associated with this expense
- Add to existing ExpenseModel and Expense entity
- Maintain backward compatibility with existing expense data

**Hive Integration** [Source: docs/architecture.md#Schema Integration Strategy]

- New Hive box: 'receipt_photos' for storing photo metadata
- Use HiveType annotations following existing patterns (typeId: 5)
- Create custom adapter for ReceiptPhoto model
- Modify existing expense box to include photoIds field

### Technical Constraints

**Technology Stack** [Source: docs/architecture.md#Tech Stack Alignment]

- Flutter 3.2.3+, Dart 3.2.3+
- Riverpod 2.4.9 for state management
- Hive 2.2.3 for local database
- image_picker 1.0.7 for photo capture
- path_provider 2.1.2 for file system access
- permission_handler 11.3.0 for camera permissions
- Follow existing Clean Architecture patterns
- Maintain platform-specific UI (Material/Cupertino)

**Performance Considerations**

- Photo storage must not impact existing expense operations
- Photo file sizes should be optimized for mobile storage
- Memory usage for photo processing should be minimal
- Photo loading should not block UI thread

**Backward Compatibility**

- All existing expense data must remain unchanged
- Existing expense CRUD operations must work without modification
- Existing expense list and detail views must continue to work
- No data migration required for existing users

**Permission Requirements**

- Camera permission for photo capture
- Storage permission for saving photos
- Gallery permission for photo selection
- Handle permission denial gracefully
